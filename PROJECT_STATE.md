# PROJECT_STATE

## Project

Lightweight collaborative document editor.

## Tech Stack

| Layer     | Technology                        | Purpose                                      |
| --------- | --------------------------------- | -------------------------------------------- |
| Frontend  | React 18.3 (hooks)                | Document editor UI                           |
| Build     | Vite 6                            | Dev server and production bundling           |
| Routing   | React Router 6                    | Client-side routes (`/`, `/doc/:id`)         |
| Styling   | Tailwind CSS 4 (`@tailwindcss/vite`) | Utility-first styling, zero config files  |
| Icons     | lucide-react                      | Navigation and document icons                |
| Editor    | TipTap 3 (`@tiptap/react`, StarterKit) | Rich-text editing and HTML serialization |
| Runtime   | Node.js                           | Server runtime                               |
| Server    | Express                           | HTTP API                                     |
| Database  | SQLite (`sqlite3` driver)         | Deterministic local persistence              |
| Testing   | Jest + Supertest (server)         | Integration tests against the Express app    |
| Transport | CORS + JSON                       | Client/server communication                  |

## Current Phase

**MVP complete**

The MVP is feature-complete: demo identities, document CRUD, owner/share
access control, TipTap editing with autosave, the owner-only share modal, and
`.txt`/`.md` import under 2 MB. The remaining items are post-MVP hardening
(real sessions, component tests, real-time collaboration).

## API Contract

Every route requires the `x-user-id` header with a seeded user id (1, 2 or 3).
Missing/invalid header → `401 Unauthorized`.

| Method | Route                        | Auth          | Description                                                        |
| ------ | ---------------------------- | ------------- | ------------------------------------------------------------------ |
| GET    | `/api/health`                | `x-user-id`   | Liveness probe, returns `{ status: "ok", userId }`                 |
| GET    | `/api/me`                    | `x-user-id`   | Returns `{ id, email, name }` for the caller                       |
| GET    | `/api/documents`             | `x-user-id`   | Returns `{ owned: [...], shared: [...] }` for the caller           |
| POST   | `/api/documents`             | `x-user-id`   | Creates a document from `{ title, content }`, returns `201` + doc  |
| GET    | `/api/documents/:id`         | owner/share   | Returns the document; `403` if the caller has no access            |
| PUT    | `/api/documents/:id`         | owner/share   | Updates `title` and/or `content`, refreshes `updated_at`; `403` if unauthorized |
| POST   | `/api/documents/:id/share`   | owner only    | Shares with `{ userId }`; `403` if the caller is not the owner     |

### Response conventions

- `401` — missing/invalid `x-user-id`
- `403` — authenticated but not allowed (not owner and not shared)
- `404` — document or target user does not exist
- `400` — invalid body (bad id, empty title, no updatable fields, etc.)

## Frontend Routes

| Route      | Component             | Status                                   |
| ---------- | --------------------- | ---------------------------------------- |
| `/`        | `Dashboard`           | Owned/shared lists, create, import, open |
| `/doc/:id` | `EditorView`          | TipTap editor, autosave, owner share modal |
| `*`        | `NotFound`            | 404 fallback                             |

## Client API Usage

`src/api.js` exports `getMe`, `getDocuments`, `getDocument`, `createDocument`,
`updateDocument` and `shareDocument`. Each takes `userId` first and forwards it
as `x-user-id`; components pass `activeUserId` from `AuthContext`.

The base URL defaults to `http://localhost:3001` and can be overridden with
`VITE_API_URL` (for example in `client/.env.local`).

## Runbook

```bash
# Terminal 1 - API
cd server
npm install
npm run db:init     # creates database.sqlite and seeds users
npm start           # http://localhost:3001
npm test            # Jest + Supertest (in-memory DB)

# Terminal 2 - client
cd client
npm install
npm run dev         # http://localhost:5173
npm run build       # production build in client/dist
```

Demo login = the user switcher in the top-right (Alice / Bob / Charlie). The
choice is stored in `localStorage` under `ajaia.activeUserId` and defaults to 1.

the app, runs `db.initialize()` in `beforeAll`, closes the connection in
`afterAll`.

| - | ----------------------------------------------------- | ------------------ |
| 1 | Alice creates a document                              | `201`, persisted   |
| 2 | Bob fetches Alice's document before being shared      | `403 Forbidden`    |
| 3 | Alice shares the document with Bob                    | `201`, appears in Bob's shared list |
| 4 | Bob fetches the document after sharing                | `200`, correct doc |
| 5 | Bob (non-owner) tries to share Alice's document       | `403 Forbidden`    |

Client verification (headless Edge + Playwright core, not committed):
dashboard renders Alice's owned document, user switch refetches into Bob's
shared list, Charlie shows empty states, Open navigates to `/doc/:id`, Create
persists a new document and navigates, active user survives reload, and no
console/page errors are emitted.

Editor verification (same headless approach, not committed): initial heading and
bold text render from stored HTML without a mount-time save, title and body
edits autosave after the debounce, toolbar buttons toggle and reflect the
cursor's active marks/nodes, H1/H2 and both list types persist, the explicit
Save button issues an immediate `PUT` and shows "Saved!", content survives a
reload, Bob gets the 403 "Access denied" state for an unshared document, and
`/doc/999999` gets the 404 "Document not found" state.

MVP verification (headless, not committed): the dashboard exposes "Import file"
with a hidden `.txt,.md` input; a 2 MB file is rejected without creating a
document; `notes.md` imports as title "notes" with line breaks preserved and

## Notes / Decisions

- SQLite keeps persistence deterministic and local; a single file ships easily.
- `DB_PATH` env var overrides the database location, which is how tests get an
  isolated in-memory database while normal runs use `server/database.sqlite`.
- Access control lives in one identity middleware plus a shared
  `loadDocumentForUser` helper for per-document checks, so rules stay consistent.
- Sharing is modeled as an explicit join table (`document_shares`) rather than
  an owner flag, keeping ownership and granted access separate concerns.
- `app` is exported from `index.js` and only listens when run directly, so
  Supertest can exercise the real middleware stack without opening a port.
- The client mirrors the seeded demo users in `AuthContext.jsx`; there is no
  login form yet, and the switcher exists to exercise 401/403 behavior.
- Dashboard effects use a cancellation flag so rapid user switching cannot
  apply stale responses.
- SQLite timestamps are UTC; the dashboard appends `Z` before formatting them
  as local time.
- Tailwind CSS 4 needs no `tailwind.config.js`; it is enabled by the
  `@tailwindcss/vite` plugin and a single `@import "tailwindcss"`.
- TipTap StarterKit v3 already bundles Underline, so `StarterKit` is configured
  with `underline: false` and the installed `Underline` extension is registered
  explicitly, avoiding duplicate extensions.
- TipTap v3 does not re-render on transactions by default; the editor passes
  `onTransaction` to force a render so toolbar active states follow the cursor.
- The editor mounts only after the document fetch resolves, so `useEditor`
  receives initial HTML directly. Mounting is excluded from autosave by
  comparing against the normalized initial HTML.
- Autosave debounces for 800 ms; the explicit Save button clears the pending
  timer, issues an immediate `PUT`, and shows "Saved!" for 2 seconds. Content is
  stored as TipTap `getHTML()`, and an empty title falls back to "Untitled
  document".
- The production bundle is ~621 kB because of TipTap, so Vite warns about the
  500 kB chunk threshold; accepted for now (code-splitting is a later concern).
- The Share button renders only when `doc.owner_id === activeUserId`; the server
  still enforces owner-only sharing, so hiding the button is purely UI. The
  modal filters recipients from `AuthContext` by owner id and reports success or
  API errors inline without closing.
- File import uses a hidden `<input type="file" accept=".txt,.md">`. The client
  rejects files at or above 2 MB before reading, derives the title by stripping
  the final extension, and navigates to the created document on success.
- Imported text is converted to escaped `<p>` blocks so line breaks survive
  TipTap's HTML storage and file contents cannot inject markup. Markdown is
  imported as plain text; no Markdown renderer is included.
- Real-time collaboration is deliberately out of MVP scope; the checklist now
  separates post-MVP hardening from completed product work.
